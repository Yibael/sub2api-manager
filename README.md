# Sub2api Manager

基于 sub2bar 功能设计的移动端优先、只读 sub2api 监控 PWA。使用 React、shadcn/ui、TanStack Router / Query / Form，以及 Bun + Elysia。

## 运行

```sh
bun install
cp .env.example .env
```

在 `.env` 中填写：

- `SUB2API_URL`：sub2api 地址，支持子路径。默认要求 HTTPS。
- `SUB2API_ADMIN_KEY`：上游 Admin API Key，仅服务端读取。
- `APP_PASSWORD`：此监控应用的独立访问密码，至少 16 个字符。
- `APP_ORIGIN`：浏览器实际访问的完整来源；开发默认 `http://localhost:5173`，生产必须 HTTPS。域名和端口需要完全匹配。
- `SUB2API_TIMEZONE`：与 sub2api 今日统计一致的 IANA 时区，例如 `Asia/Shanghai`。

```sh
APP_ORIGIN=http://localhost:5173 bun run dev
```

使用 `http://localhost:5173`。开发 API 默认监听 `127.0.0.1:3001`，由 Vite 同源代理。

未配置 sub2api 时显示连接设置页面。配置完成后需先登录，再从账号目录选择关注的账号、填写订阅配置。应用不会预填账号、消费或订阅金额。

如默认端口已占用：

```sh
DEV_PORT=5188 PORT=3008 APP_ORIGIN=http://localhost:5188 bun run dev
```

## 核心行为

- 概览、账号管理、账号详情、消费统计和设置；手机底部导航、桌面侧栏、浅色 / 深色模式。
- Pin 与排序、OAuth 订阅配置、今日标准用量、额度窗口与 API Key 本地限额。
- 概览展示今日消费、周期消费、当前并发、今日标准用量；7日额度估算仅在 OpenAI OAuth 账号中展示。消费支持指定时区、排除 Admin、金额隐藏；成本按周期配置。
- 消费统计聚合为一个全站用户消费榜，可切换本小时、今天、近7天、近30天，按实际消费显示前 12 名。近7天和近30天包含今天，按统计时区的自然日计算；只查询当前选中的范围，使用 sub2api 汇总接口，不拉取消费明细。本小时按上游时区的整点分桶，`SUB2API_TIMEZONE` 需与上游时区一致。
- 浏览器只请求应用后端，后端携带 Admin Key 查询 sub2api。
- **共享缓存**：5 秒间隔内，设备 B 直接复用设备 A 的查询结果，不显示缓存命中提示。
- **并发去重**：相同账号同时查询只执行一次；重叠账号列表按账号复用。
- **没有后端轮询**：缓存到期只等待下一次请求。关闭所有设备后，不会启动后续刷新。正在进行的一轮请求有超时上限。
- 自动刷新复用共享缓存；手动刷新跳过正常缓存间隔，额度同时向上游发送 `force=true`，但仍遵守失败退避和 429 冷却。
- 概览按钮只刷新额度，倒计时对应额度通道；统计按钮刷新账号状态、消费统计和当前选中的用户榜单，不显示倒计时。自动刷新间隔从上一次请求完成时起算，手动刷新完成后重新计时，保留原有按钮文案与 loading 样式。
- 用户榜单刷新间隔取消费间隔与 30 秒的较大值。手动刷新跳过 manager 缓存并重新请求上游；sub2api 排行榜自身约 5 分钟缓存、用户趋势约 30 秒缓存，现有接口没有绕过参数，数据新鲜度仍受上游限制。
- 间隔按账号和数据范围执行；不同账号、不同日期范围或时区可各自查询，并非整个实例每 5 秒只能发一个 HTTP 请求。上游同时最多执行 4 个请求。
- 消费总计和 Admin 小计按实际查询参数共享缓存，切换 Admin 开关不会重复读取同一总计。429 遵守 `Retry-After`，冷却期间整个上游连接不再启动请求。
- 失败保留同范围旧值并显示失败；没有历史结果显示未知。跨日、跨周期不会复用不匹配的统计。
- 单人工作空间：关注账号与排序、订阅成本与续费日、货币符号、统计时区、Admin 开关和刷新间隔统一保存到 `DATA_DIR/workspace.json`，所有设备共用；主题和隐藏金额仅保存在当前设备。
- 配置保存成功后才显示完成提示；其他设备前台约 5 秒同步，重新进入前台或恢复网络时立即读取。并发修改通过版本号检查，冲突时读取最新配置并提示重试。

## Passkey 与配置迁移

首次使用访问密码登录，进入 **设置 → 登录与安全**，为 Passkey 命名并按系统提示添加。已配置 Passkey 且浏览器支持时，进入登录页或锁定后返回前台自动尝试一次验证；取消或失败后保留手动 Passkey 按钮和访问密码，不连续弹窗。Safari 17.4+ 支持无点击发起验证；旧浏览器若要求用户手势，可点击按钮继续。可以添加多个 Passkey、重命名或移除；连续前台使用不再每 5 分钟要求重验。关闭 / 重新打开 / 刷新页面、锁屏或页面转入后台后，返回时重新使用 Passkey 或访问密码验证。浏览器无法可靠区分锁屏、切换标签页与最小化，因此统一按页面隐藏锁定；普通失焦和应用内部导航不锁定。

本次认证接口为不兼容更新：旧客户端的登录请求不能直接沿用，部署后需加载新前端并重新登录。已有 PWA 请先更新并重载；如果停留在旧版本，请关闭该站点所有页面和 PWA 后重新打开。业务配置和已登记的 Passkey 保留。

生产入口需 HTTPS，`APP_ORIGIN` 必须与实际来源完全一致。Passkey 绑定站点域名；更换域名后需要使用密码登录并重新添加。服务端只保存公钥与凭证信息，私钥由设备或系统密码管理器保管；移除凭证后，通过它创建的应用会话也会失效。

升级后首次登录，如服务器尚未初始化配置且浏览器发现旧配置，会提示选择“迁移本机配置”或“使用服务器配置”。先在配置最完整的设备完成迁移；已初始化的服务器配置不会被其他设备的旧配置自动覆盖。原 `intervals.json` 在首次创建工作空间时读取，此后以 `workspace.json` 为准。

工作空间 ID 保存在数据卷中，更换上游 Admin Key 不会更换配置身份。配置备份升级为 v2，包含刷新间隔，并兼容原实例的 v1 备份；导入会替换共享业务配置和当前设备的显示偏好。配置导出不包含 Passkey，需要完整恢复时备份数据卷中的 `workspace.json`。

## 生产部署

```sh
bun run build
APP_ORIGIN=https://manager.example.com bun run start
```

生产由 Elysia 同时提供 `dist` 静态资源、SPA 路由回退和 `/api`。在前面配置 HTTPS 反向代理；代理到 `127.0.0.1:3001`，保持路径与请求 `Origin`。不要将管理员密钥放入任何 `VITE_` 环境变量。

本地开发和 Docker 共用一份 `.env`。已有文件时直接修改，无需再次复制。Docker Compose：

```sh
cp .env.example .env
chmod 600 .env
cp docker-compose.example.yaml docker-compose.yaml
# 编辑 .env，填写真实连接、访问密码和 HTTPS 来源
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 120
```

`docker-compose.example.yaml` 为部署模板；实际使用的 `docker-compose.yaml` 已被 Git 忽略，可按部署环境修改。已有配置文件时不要覆盖，更新时按需合并模板变更。

镜像采用多阶段构建，服务端打包后无需运行时 `node_modules`；容器使用非 root 用户和只读根文件系统。共享业务配置和 Passkey 公钥凭证保存到 `/app/data` 命名卷。宿主端口默认只绑定 `127.0.0.1:3001`，通过现有 HTTPS 反向代理对外提供访问。

健康检查只读取容器内配置接口，不触发 sub2api 查询。详细环境变量、HTTPS 接入、更新和跨架构构建见 [docs/docker.md](docs/docker.md)。

当前使用单进程缓存与内存会话，部署一个应用进程；进程重启后需要重新登录，监控缓存在下一次请求时重建，业务配置和 Passkey 保留。多副本共享缓存和后台推送不在本版范围。

## PWA

生产构建生成 Manifest 和 Service Worker。iPhone 上在 Safari 打开 HTTPS 地址，通过分享菜单添加到主屏幕。应用已包含安全区、独立窗口模式、触控布局和更新提示。

仅预缓存静态应用资源，`/api` 响应不会进入 Service Worker 缓存。持续前台使用时断网保留内存数据；转入后台后锁定并清理受保护数据，离线冷启动展示应用外壳和连接错误，不读取持久化账号快照。
