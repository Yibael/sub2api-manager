# 技术与页面设计

## 已确认的技术栈

- React + TypeScript + Vite
- TanStack Router、TanStack Query、TanStack Form + Zod
- shadcn/ui（Radix Nova）+ Tailwind CSS 4
- Bun + Elysia；不直接从浏览器查询 sub2api
- vite-plugin-pwa / Workbox
- Vitest；页面交互通过 computer use 检查，不引入 Playwright 测试套件

## 查询与共享缓存

浏览器 → 同源 Elysia API → sub2api。Admin Key 只由服务端读取。公开响应按字段白名单生成，不回传账号 credentials、任意 extra 或上游错误正文。

后端没有轮询计时器、Cron、后台刷新或自动重试任务。每次请求按以下顺序处理：

1. 相同键已有进行中的请求：共用该 Promise。
2. 上次查询完成后尚未达到刷新间隔：直接返回缓存，不附加缓存命中提示；成功和失败都遵守间隔。
3. 失败退避尚未结束：返回上次数据及失败原因。
4. 否则执行一次查询并保存成功结果；失败只更新错误和下次允许查询的时间。

缓存到期不会触发任何操作。停止前端请求后，后端不会再开启新的刷新轮次。已进入服务端的一轮有限请求可以完成；单次 HTTP 请求（含排队）20 秒超时，多步骤查询有 30 秒总信号。共享请求不绑定到某一个设备的断连，避免设备 A 取消时误伤正在等待的设备 B。

刷新间隔按上次查询完成时间计算，缓存命中不续期。改变间隔保留数据与进行中的请求；失败后的下一次查询同时满足新间隔和既有失败退避。自动刷新遵守缓存间隔；手动刷新传递 `force=true` 跳过正常缓存有效期，上游额度批量及兼容回退接口同样发送强制参数，但保留失败退避和 429 冷却。强制请求等待同键的普通在途请求结束，再读取一次；多个强制在途请求共用结果。额度刷新只强制额度通道，用于检查账号是否可读取的状态仍复用共享缓存。

间隔约束适用于同账号、同通道、同查询范围，不是全实例 HTTP 请求之间的全局间隔。不同账号或消费日期范围、时区、用户筛选可以分别查询；分页和批量接口兼容回退属于一轮查询的有限步骤。所有真实 HTTP 请求共享最多 4 个并发槽。收到 429 后，整个上游连接进入冷却，遵守秒数或 HTTP 日期形式的 `Retry-After`，没有有效指示时等待 30 秒；已在途请求可结束，尚未出队的请求不会继续发出。冷却到期后仍需客户端请求才会重试。

| 通道 | 默认 | 缓存粒度 |
| --- | --- | --- |
| 账号目录 | 60 秒 | 当前实例目录 |
| 账号状态 | 5 秒 | 账号 ID |
| 今日标准用量 / 请求 / Token | 5 秒 | 账号 ID；数据另外标记上游统计日期 |
| 上游额度与窗口费用 | 30 秒 | 账号 ID |
| 消费总计及用户小计 | 15 秒 | 账号 ID + 起止日期 + 时区 + 用户 ID（总计为空） |
| Admin 名单 | 15 秒 | 当前实例 Admin 目录；跟随消费间隔 |

每个 Monitor 只绑定一个实例与凭据。更换凭据重启进程后自然隔离缓存。今日统计的日期边界使用 `SUB2API_TIMEZONE`，必须与上游的自然日口径一致；跨日后不展示昨日值，等原间隔结束后的下一次客户端请求再读取，日期变化不重置限流。消费使用用户明确配置的时区和显式日期参数，新日期或周期属于不同查询范围，不复用旧范围数据。

缓存按账号复用，设备选择 `[1, 2]` 与 `[2, 3]` 时，账号 2 不会重复查询。批量读取为尚未缓存的账号构建请求；旧服务端不支持额度批次时，回退为单账号查询，并记住该能力。普通 OpenAI / Anthropic API Key 不查询 OAuth 额度。

单进程内存缓存，单缓存最多 5000 个键；仅按需清理完成至少 10 分钟且冷却已结束的旧键，不驱逐正在执行、当前请求引用或仍处于冷却的键。容量不足拒绝新增范围，避免驱逐限流状态后立即重查。当前不支持多副本之间共享缓存，生产部署使用一个应用进程。重启后内存缓存和冷却重置；若以后扩容或要求跨重启保留间隔，需要把缓存、请求协调和会话迁移到共享存储。

## 登录与工作空间

单人单工作空间，无用户注册与多人权限模型。访问密码保留原有环境变量方式；另通过 SimpleWebAuthn 注册和验证 Passkey。注册、重命名和移除要求本次页面已验证；取消固定 5 分钟重验及 `/api/reauth` 接口。关闭、重载、锁屏或页面转入后台后，重新进入需使用密码或 Passkey 验证，内部导航与普通 blur 不锁定。

RP ID 为 `APP_ORIGIN` 的 hostname，验证完整 Origin；要求可发现凭证和用户验证。挑战仅在内存保存 2 分钟、单次使用，注册挑战绑定当前登录会话。服务端保存公钥、计数器、名称和使用时间，不保存私钥。移除 Passkey 会撤销通过该凭证登录的会话。会话与挑战 Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 下为 Secure；保留服务端会话的原有 7 天上限。登录响应额外返回随机页面验证令牌，只保存在当前 document 的内存中。受保护 API 必须同时提供匹配的 Cookie 与 `X-Page-Session`，Cookie 单独不能重新进入；新 document 不恢复令牌。

锁定监听 visibilitychange(hidden)、pagehide、freeze 和 BFCache 恢复，清除页面验证令牌、受保护查询缓存并取消请求；通过 JSON Beacon 尽力撤销对应服务端会话。关闭事件丢失或断网时，页面内存令牌也无法被下一次打开恢复。旧页面延迟发送的 lock 请求不能撤销新登录。API 和验证流程通过本地世代检查拒绝锁定前的晚到响应，避免重新填充缓存或解锁新页面。

系统 WebAuthn 弹窗触发隐藏时先遮挡内容，验证成功且页面可见后恢复；取消或仍在后台则锁定。pagehide / freeze 始终锁定，即使当时正在验证。页面隐藏事件不能可靠区分锁屏和切换应用，因此采用统一策略。

`DATA_DIR/workspace.json` 保存随机稳定工作空间 ID、WebAuthn user handle、共享配置、修订号与 Passkey 信息。写入串行执行，通过临时文件原子替换，文件权限为 0600。配置 PATCH 检查客户端修订号，过期请求返回 409；失败不更新前端成功状态。文件损坏导致启动失败，不自动丢弃配置。

浏览器前台每次工作空间请求完成约 5 秒后再次读取，保存中 / 隐藏 / 离线时停止定时读取；返回前台和恢复网络重新同步。旧或相同修订号的响应不覆盖较新数据。每台设备的主题和金额隐藏使用独立 localStorage 键。

首次创建工作空间保留旧实例 ID 并读取旧 `intervals.json`；浏览器旧配置需明确选择迁移，已初始化的服务器配置不会自动被旧设备配置覆盖。v2 配置导出包含刷新间隔，不包含 Passkey；兼容旧实例 v1 备份。更换上游 Admin Key 不改变持久化的工作空间 ID。

前端数据通道使用请求完成时间设置下一次 setTimeout，不使用固定开始时间轮询；手动刷新取消当前客户端请求并强制读取，完成后重新计时。概览刷新和倒计时只对应额度；统计页刷新状态及消费，不查询额度或今日标准用量，不显示倒计时。

## 数据归属

- 服务端环境：Admin Key、应用访问密码；进程内存：会话、挑战、共享监控缓存与冷却。
- 服务端文件：稳定工作空间身份、Pin 顺序、订阅价格与续费日、统计偏好、刷新间隔、Passkey 公钥及凭证信息。
- 当前设备：主题、金额隐藏状态，以及由系统保管的 Passkey 私钥。
- Service Worker：只预缓存静态应用资源；不缓存 `/api` 响应或 Admin 数据。
- 运行环境：仅连接配置的真实上游；未配置时展示连接设置，已配置时要求登录。新实例的关注账号和订阅配置均为空。
- 自动化测试：固定响应仅在 `tests/fixtures` 内，由测试注入 Monitor，不进入应用运行时或生产容器。

## 统计约定

界面统一使用标准用量、消费、额度、周期、成本。今日标准用量使用 `standard_cost`，概览汇总全部已关注账号；今日消费和周期消费统一使用 `total_actual_cost`，跟随统计时区和 Admin 开关。`cost` 与 `user_cost` 不作为另一套消费指标展示。7日额度估算仍采用原窗口算法，仅在 OpenAI OAuth 账号中展示。缺失和失败不填零。

只有已关注且完整配置价格、续费日的 OAuth 账号计入概览和统计中的消费汇总；今日标准用量汇总全部关注账号。账号详情可以独立查看自身周期；未配置订阅及 API Key 账号也可通过 `/spending/today` 查询今日消费，该接口与周期查询共享按实际查询参数隔离的消费原始缓存。Admin 开关不进入原始总计缓存键，不同口径的设备共用相同总计。订阅价格可为零，成本不按天摊销。不同账号各自分割订阅周期，短月取月末，后续月份恢复原续费日。展示周期终点为下次续费日前一天，实际请求只查询到今天。

排除 Admin 时分页读取当前 Admin 名单，先查询同范围 Admin 小计，再查询总计，以 Decimal 相减；不是原子结算快照。必要结果缺失时不显示部分汇总。两个消费范围分别处理错误。货币符号只控制显示，不执行换汇。

消费结果按日期范围、时区、Admin 开关保留最后一次完整计算。每次按需从原始缓存重新计算，投影层本身不增加 TTL，避免两层缓存使过期时间叠加；投影的更新时间为所依赖样本中最早的时间。部分数据读取失败时保留最后完整结果并标记错误，不把新旧部分结果混算成成功值。账号状态读取失败时不继续启动依赖该账号的额度或消费请求。

## iOS 与离线

目标兼容 Safari / iOS 16.4+，Vite 显式构建到 Safari 16.4。包含主屏幕图标、standalone Manifest、安全区、动态视口、44px 主要触控区域、16px 移动输入、底部导航、减少动画偏好。

页面隐藏时锁定并取消前端请求、清理受保护查询缓存；返回前台验证后恢复按需请求。关闭再离线启动可加载应用外壳并显示连接错误；不持久化受保护的账号快照。持续前台使用时断网可显示内存数据并提示离线，转入后台后需在线重新验证。新版本就绪时提示用户更新，不自动打断表单。

没有实现后台监控、Web Push 或对 sub2api 的账号管理写操作。

## 产品文案

页面标题不添加英文眉题或营销副标题。指标卡仅显示名称、数值和图标；不添加底部解释行。账号平台、类型、周期、重置时间和数据异常属于必要信息，应保留。刷新调度、缓存、凭据存储等实现说明仅出现在开发文档中，不进入页面、页脚或保存提示。安装操作、表单校验以及会替换用户配置的操作保留简短提示。
