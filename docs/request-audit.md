# Sub2API 请求审计

审计日期：2026-10-04。范围为 Manager 浏览器触发路径、服务端所有 `upstream.request` 调用和两个业务写入入口。

## 规则

- 轮询：仅前台运行，上一次读取完成后再等待配置间隔；普通轮询使用 `force=false`。
- 非轮询自动读取：卡片或独立查询分组距离视口 200px 以内时读取一次；本次页面失败后也不自动重试，后续用户手动刷新。
- Sub2API 业务写入：先检查当前值，再显示二次确认框，最后凭服务端一次性凭证写入。
- 用户主动刷新、检查连接、检查变更及确认保存属于明确操作，按对应接口执行有限请求。

## 出站路径

以下路径均相对 `/api/v1/admin/`。表中间隔是 Manager 正常缓存间隔，从查询完成时计算；未列出的账号依赖读取复用共享账号状态缓存。

| 功能 | Sub2API 请求 | 自动触发方式 | 正常缓存 / 限制 |
| --- | --- | --- | --- |
| 账号目录 | `GET accounts`，分页 | 资源账号页前台轮询 | 60秒，实例级 |
| 账号状态 | `GET accounts/:id` | 概览、详情前台轮询 | `intervals.status`，默认5秒，账号级 |
| 自动用卡配置 | 共用 `GET accounts/:id` | 详情前台轮询 | 共用状态缓存；初始化完成前开关显示加载中 |
| 今日标准用量、请求、Token | `POST accounts/today-stats/batch` | 概览、详情前台轮询 | `intervals.status`，默认5秒，账号级去重 |
| OAuth 额度 | `POST accounts/usage/batch`；兼容回退 `GET accounts/:id/usage` | 概览、详情前台轮询 | `intervals.quota`，默认30秒；API Key 不调用此通道 |
| 今日及周期消费 | `GET usage/stats` | 概览、详情前台轮询 | `intervals.spending`，默认15秒，账号 + 日期 + 时区 + 用户 |
| Admin 名单 | `GET users?role=admin`，分页 | 排除 Admin 的消费或榜单读取时按需获取 | 概览/详情使用消费间隔；统计使用独立 30 秒共享快照 |
| 用户消费榜及趋势 | `GET dashboard/users-ranking`、`GET dashboard/users-trend`；排除 Admin 可能读取 `usage/stats` | 当前范围接近视口时读取一次，之后手动刷新或切换范围 | 独立 30 秒共享快照，无刷新调度，范围级 |
| 模型榜 | `GET dashboard/models`；排除 Admin 按用户读取相同接口 | 当前范围接近视口时读取一次，之后手动刷新或切换范围 | 独立 30 秒共享快照，无刷新调度，日期 + 时区 + 用户 |
| 分组目录 | `GET groups`，分页 | 接近视口时读取一次 | 60秒，之后仅手动刷新；保存仅更新已确认值 |
| 重置卡与 Credits 初读 | 共用 `GET accounts/:id` 中的快照 | 对应查询分组接近视口时读取一次 | 共用状态缓存，之后手动刷新 |
| 可邀请数量初读 | 共用 `GET accounts/:id` 中的快照 | 对应查询分组接近视口时读取一次 | 共用状态缓存，之后手动刷新 |
| 查询最新重置卡与 Credits | `POST openai/accounts/:id/quota/refresh` | 仅对应刷新按钮 | 手动 force；账号级在途去重，失败退避从30秒起 |
| 查询最新可邀请数量 | `POST openai/accounts/:id/referrals/refresh` | 仅对应刷新按钮 | 手动 force；账号级在途去重，失败退避从30秒起 |
| 订阅与成本 | `GET accounts/:id`、`GET usage/stats` | 卡片接近视口时读取一次，之后局部手动刷新 | 独立 30 秒共享快照，不读取刷新间隔设置 |
| 手动用卡预览 | `GET accounts/:id` + `POST openai/accounts/:id/quota/refresh` | 仅打开确认界面 | 一次 quota 查询提供额度与权益，保留失败退避 |
| 手动用卡执行 | `POST openai/accounts/:id/reset-quota` | 仅二次确认后 | 账号共享写锁、SQLite 操作唯一保护，不自动重试 |
| 检查连接 | `GET accounts`，分页 | 仅设置内的检查按钮 | 共用账号目录缓存 |
| 分组倍率检查及保存前复核 | `GET groups/:id` | 仅检查变更、确认保存 | 每次操作读取最新值，共用并发及429冷却 |
| 分组倍率写入 | `PUT groups/:id` | 仅二次确认后 | 一次性凭证，写入不重试 |
| 自动用卡检查及保存前复核 | `GET accounts/:id` | 仅切换开关、确认保存 | 每次操作读取最新值，共用并发及429冷却 |
| 自动用卡写入 | `PUT accounts/:id` | 仅二次确认后 | 一次性凭证，写入不重试 |

权益初读只提取 Sub2API 账号快照，不调用其 quota/referrals 刷新接口。账号状态轮询可能更新 Manager 的账号缓存，已展示的权益只在首次读取或用户主动刷新时更新。

重置卡与 Credits 共用一个 quota 刷新接口；邀请使用独立接口。一次刷新只发出一个对应的 Sub2API 刷新请求。Sub2API 在其内部可能向真实上游发出多个请求。

业务写入指变更上游配置或执行消耗类操作。批量统计 POST 和权益刷新 POST 按查询处理；权益刷新会写入查询快照缓存，当前沿用查询按钮的交互，不新增确认。管理器自身的关注、订阅、设置及 Passkey 操作只写入 Manager。

## 限流与强制刷新

所有服务使用 `server/index.ts` 创建的同一个 Upstream 实例，真实 HTTP 请求最多4个并发。排队时间计入20秒请求超时，获得并发槽时再次检查中止信号和429冷却。

429 冷却在连接内共享，遵守秒数或 HTTP 日期形式的 `Retry-After`；无有效值时等待30秒。冷却内的排队请求不会继续发出，写入也遵守同一规则。服务端没有后台轮询、自动重试或冷却结束后的自动任务。

`DemandCache` 按账号、通道和统计范围共享数据与在途请求。正常请求从完成时间计算TTL；失败保留最后成功结果，指数退避上限10分钟。多设备及重叠账号批次共用缓存。手动 `force` 跳过正常TTL，仍遵守失败退避和429冷却；普通在途请求结束后再强制读取，多个同时强制请求共用结果。

这是一组按通道间隔、共享并发和429冷却的限制；没有全实例每秒请求数的固定限制。分页、旧接口回退和排除 Admin 所需的小计均为一轮读取内的有限步骤，共用并发槽和冷却。

Sub2API 用户榜、趋势及模型榜接口自身可能命中其统计缓存；Manager 的 force 不能绕过上游未提供绕过参数的缓存。额度接口传递 force，权益刷新调用专用实时查询接口。

## 写入门禁

两个业务写入口均执行以下流程：

1. 预览直接读取最新配置，只生成变更预览，不写入上游。
2. 前端展示目标账号或分组、新旧值及影响，等待用户确认。
3. 服务端凭证绑定登录会话、资源ID和确认目标，2分钟有效，单次消费；取消、重复、过期及跨会话凭证拒绝写入。
4. 保存前再次读取并检测并发变更，同一资源写入互斥。
5. 只发送允许变更的字段；写入不重试、不跟随重定向。核对返回值后才显示成功，成功或结果不明均作废相关缓存。

已核对的 Sub2API 接口没有这两种配置的条件更新，其他客户端在最后复核与写入之间的并发修改仍不能完全阻止。

## 本次修复及验证

修复前，权益在组件挂载时立即读取；分组目录在挂载、缓存失效或前台恢复时可能自动重读。现在两者使用接近视口激活和一次性手动 Query，滚动离开再回来、计时器、焦点、重连和失效均不增加自动读取。非轮询请求标记 `meta.poll=false`，后台暂停轮询不会取消正在完成的一次性读取。

本地 fixture 浏览器验证：

- 实际视口528×560，权益分组顶部910px / 1117px：两者均未请求。滚动280px后仅 quota GET 增加一次；继续滚动后 referrals GET 增加一次。
- 经过多个状态及额度轮询周期，滚走再返回，两种权益 GET 均未增加。
- 点击 quota 刷新只增加一个 quota refresh，点击邀请刷新只增加一个 referrals refresh。
- 分组目录等待超过60秒并切回页面，没有自动重读；手动刷新增加一次请求。开发模式首次读取也仅发出一次 GET。
- 自动用卡、分组倍率均出现二次确认，取消后没有 PUT。服务端测试覆盖无凭证、重复、过期、跨会话、并发变更和写入不重试。

测试使用本地 fixture，不对生产 Sub2API 写入。传输层的并发、429、排队超时和缓存限流由测试验证；浏览器 fixture 自身不连接真实上游。
